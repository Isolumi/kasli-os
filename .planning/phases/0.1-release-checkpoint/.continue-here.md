<current_state>
Kasli is at a usable 0.1-style checkpoint. The repository is on branch
`development`. The code version in `CMakeLists.txt` is `0.1.2`, and the latest
code baseline before this checkpoint documentation was `ea8c71c`.

The prototype is not a Linux distro. It is a local read-only daemon and CLI that
exposes typed OS inspection tools, audits calls, and can answer questions
through a local model using curated evidence.
</current_state>

<completed_work>

- Read-only daemon `kaslid` and CLI `kasli` are implemented.
- Fedora RPM packaging is implemented and installs `/usr/bin/kasli`,
  `/usr/bin/kaslid`, and the user systemd service `kaslid.service`.
- Installed CLI autostarts the user daemon when the default socket is missing
  or stale.
- Registered read-only tools: `system.info`, `disk.usage`,
  `hardware.summary`, `network.summary`, `power.status`,
  `packages.recent_changes`, `packages.list`, `systemd.units.list`,
  `systemd.unit.status`, `services.failed`, `services.enabled`,
  `journal.query`, and `service.diagnose`.
- Model answering works through Ollama and can also be configured for
  LM Studio/OpenAI-compatible local servers.
- Official Ollama `0.23.0` with `gemma4` was verified working. Fedora's
  distro-packaged `ollama-0.9.4-4.fc43` failed because it reported version
  `0.0.0` and did not support the `gemma4` model architecture.

Verified commands at checkpoint:

```sh
ctest --test-dir build-fedora --output-on-failure
# 100% tests passed, 0 tests failed out of 160

kasli --tools-list
# ok=true with the full read-only tool registry

kasli --ask "what os is this?" --ask-tool system.info
# ok=true; answered Fedora Linux 43 from system.info evidence
```
</completed_work>

<remaining_work>

- Design the next user-facing slice. The strongest candidate is natural

- Defer mutating actions, package changes, service restarts, config edits, and
  rollback operations until the permission broker and rollback design exist.
</remaining_work>

<decisions_made>

- Keep 0.1 as a daemon and CLI product, not a full Linux distro. A distro/remix
  should wait until the daemon, policy, rollback, packaging, and update channel
  are mature.
- Keep all implemented tools read-only for now.
- Keep the model untrusted: it receives bounded evidence after tools run, and it
  never calls tools directly.
- Prefer official Ollama for `gemma4` on Fedora. The Fedora package was not
  suitable for this model at the time of testing.
- Prioritize usability next because the core path works but is still
  developer-shaped.
</decisions_made>

<blockers>

- No current code blocker for the 0.1 checkpoint.
- External packaging caveat: the local RPM exists, but there is no hosted DNF
  repository, package signing, or update channel yet.
- External model caveat: Fedora's `ollama` package failed with `gemma4`; users
  need clear docs or diagnostics that point to official Ollama.
</blockers>

<context>
The most important product gap is not another low-level tool. The next user
should not need to know the exact tool names or debug model setup by reading
JSON errors. The next phase should make the CLI feel intentional: ask a normal
question, let Kasli choose safe read-only evidence, and provide `doctor`-style
setup checks when the local daemon or model provider is not ready.
</context>
